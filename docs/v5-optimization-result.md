## 实际完成

1. **输入与验证可恢复**：HTTP返回202前持久化患者原话；EXTRACT后保存候选；VERIFY_EXTRACT通过后原子更新状态、血压、服药和Trace。提取失败保留原话，验证超时保留候选，恢复时从对应阶段继续，不跳过验证、不重复记录。
2. **规划上下文精简**：同一条已发布回复只传一次，相同有效工具结果不同时占据本轮与历史列表。原始审计Trace不删减；不同查询及新事实仍参与后续决策。
3. **完成评估复用**：仅复用相同上下文下成功返回的`continue`结果。事实、患者输入、风险、工具结果、问题处理或规划意图变化立即失效；失败结果和结束结果不缓存。安全检查优先。
4. **限制无进展执行成本**：同一次输入的内部恢复累计PLAN预算；规划和自动内部恢复共享请求时间窗口。达到预算只暂停，不判完成，不代替LLM决定问什么。新患者输入重新开始预算。
5. **模拟患者更可信**：真实模式必须给出自然回答、事实标识及证据，并经过独立语义验证；事实ID不能直接跳过验证。仅离线脚本允许已有的事实渲染。未知问题安全澄清；恢复后保留实际已披露字段；不能回答的细节不编造、不反复复述全部档案。
6. **修复安全误拦与历史可追溯**：就医建议复用已有否定感知处方守卫，避免将“不要增加药物剂量”误判为加药指令并替换整段回复。危险指令仍拦截；实际服药日期沿用旧detail格式保存，不改表结构。
7. **现有页面和Trace保持一致**：原页面等待时限覆盖多阶段处理，显示尚未服药/部分完成；React结束后禁用发送并防止旧请求覆盖新请求。双Agent页面显示实际验证/重试/暂停事件，可手动恢复可恢复暂停，不伪造决策或患者回答。

## 核心执行机制

```text
主动任务 / 双Agent / 原有聊天接口
    → 读取患者状态与历史（历史不是本次确认事实）
    → 保存本次真实输入
    → EXTRACT → 类型、数值与原话证据检查 → 保存候选
    → VERIFY_EXTRACT → 原子应用已核实事实
    → 独立安全检查
    → PLAN：LLM自主选择提问、工具或结束申请
        → 工具参数与安全检查 → 执行/复用有效结果 → 回到PLAN
        → 回复事实及处方检查/VERIFY_RESPONSE → 发布问题
        → COMPLETE与最低业务、安全校验 → 完成/部分完成/继续
    → 事实依据的报告 → 授权医生/家属视图与站内消息
```

新的输入/候选checkpoint主要落在V5 Runtime及其API入口；原`/api/trigger`、`/api/chat`保留已有同步接口及响应契约。
短回答和复杂语义继续由现有V5提取/验证链结合上一问、患者状态与目标理解；本批没有用新增正则或固定问卷替代语义模型。
已完成主题仍允许因新信息补充核实；无法回答和拒答保留未知项，可由模型申请部分完成。
安全筛查仍依据实际问诊范围与原话证据，不能把笼统“挺好”视为全部危险症状排除。

### 性能与效果对比

唯一具有同一输入基线的微型比较：重复上下文样本的序列化PLAN载荷从4320字符降到3673字符，减少647字符（14.98%）；同一工具结果由出现2次降为1次，实际PLAN调用仍2次。
这是确定性样本字符数，不是token测量、真实模型性能或全任务平均提升。
另有回归证明同一事实连续两次申请FINISH且均需继续时只调用一次COMPLETE；新事实或风险变化后重新评估。
没有可靠的前后真实完成率、自然度或延迟基线，未制作此类提升百分比。评测原权重和通过标准保持，主观指标显式标记需人工或独立模型审阅。

### 真实模型结果与停止范围

曾尝试两次稳定场景真实运行，分别记录连接异常和PLAN超时；最小连通性生成同样超时。没有获得可用于验收的完整真实患者对话。
已有错误Trace保留，未把脚本对话当作真实模型输出。按用户“DeepSeek服务器崩掉了，不用测了”的指示，后续真实测试全部停止，也没有安排后台重测。
尚未验证稳定、异常和危险症状三类真实双Agent完整验收，不能仅凭当前离线结果认定真实对话已经稳定。
